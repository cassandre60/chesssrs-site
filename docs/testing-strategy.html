Deterministic Testing & Quality Gates

How quality invariants are mechanically enforced through deterministic gates, anti-weakening tripwires, and testing budgets.

Source in app repo: TEST_STRATEGY.md
App version: v1.4.0
Licence: GPL-3.0

1. The Deterministic Quality Gate Hierarchy

ChessSRS enforces an automated referee pipeline that mechanically verifies every pull request before code reaches main:

Gate Name Description & Enforcement
G01 Format Verification dart format --set-exit-if-changed with strict line width 100.
G02 Static Analysis flutter analyze --fatal-infos. Zero warnings, zero hints allowed.
G03 Banned API Gate scripts/gates/banned_apis_check.py prevents Flutter imports in domain and unclocked DateTime.now in schedulers.
G05 Spec Traceability scripts/gates/spec_trace_check.py asserts that active tests cite every INV-xxx ID from SPEC.md.
G08 Anti-Weakening Tripwire Diffs commits against origin/main to detect and block deleted assertions, loosened tolerances, or skipped tests.

2. The G08 Anti-Weakening Tripwire

AI agents and fatigued engineers frequently "fix" failing tests by quietly weakening them: deleting assertions, adding @skip annotations, widening numerical tolerances, or adding blanket lint suppressions.

Gate G08 (scripts/gates/test_weakening_check.py) parses git diffs to detect:

  • Any deleted expect(...) call without a compensating assertion.
  • Introduction of // ignore: or // ignore_for_file: comments.
  • Modification of benchmark tolerances or ratchet baselines.

If any test weakening is discovered, CI halts immediately.

3. Local Test Budgets (Preserving Hardware)

The Local Machine is Not a Build Server

Running 1,400+ Flutter tests repeatedly saturates laptop CPUs, pins fans at 100%, and throttles battery life. Local development follows strict budget rules:

  • Inner loop: Run only the targeted test file using fvm flutter test test/... --plain-name 'test name'.
  • Full test suites: Delegated to GitHub Actions runners on push.
  • Release builds: Release compilation (R8, AOT) is never performed on developer machines; artifacts are built on GitHub Actions runners.

4. The Escape-to-Gate Flywheel

When a bug slips past existing checks, ChessSRS follows a mandatory remediation flywheel (docs/ESCAPE_TO_GATE.md):

  1. Failing Regression Test: Write a targeted test that fails 100% reliably on current code.
  2. SPEC Assignment: Formulate a new invariant in SPEC.md naming the failure condition.
  3. Red-Team Corpus Addition: Add adversarial PGN fixtures or malformed inputs to redteam/.
  4. Root Cause Fix: Apply the minimal architectural fix that resolves the issue cleanly.
  5. Escapes Log Update: Record the incident in docs/escapes-log.md.
