Developer Guide & Toolchain

Prerequisites, FVM setup, worktree-per-task workflow, code generation, and running ChessSRS locally.

Source in app repo: CLAUDE.md
App version: v1.4.0
Licence: GPL-3.0

1. Prerequisites & FVM Setup

ChessSRS requires the exact Flutter toolchain pinned via Flutter Version Management (FVM):

Installing FVM & Flutter SDKBash
# Install fvm (if not already installed)
dart pub global activate fvm

# Inside the ChessSRS repository root:
fvm install
fvm flutter --version

Always prefix commands with fvm (e.g. fvm flutter pub get, fvm flutter run).

2. Worktree-per-Task Workflow

To prevent dirty state contamination across agents and branches, every engineering task takes place inside its own Git worktree:

Creating a Task WorktreeBash
# Create branch and isolated worktree
git worktree add ../chesssrs-feature-slug -b feat/area-feature-slug origin/main
cd ../chesssrs-feature-slug

# Bootstrap dependencies and codegen
fvm flutter pub get
fvm dart run build_runner build --delete-conflicting-outputs
Worktree Isolation Invariant

Never run git commands that write outside your worktree. Never run git add -A blindly. Stage touched files explicitly by name.

3. Code Generation (build_runner)

ChessSRS uses Freezed for immutable data classes, Riverpod generators for dependency injection, and drift for SQLite queries. Generated files (*.freezed.dart, *.g.dart) are gitignored:

Running CodegenBash
# Run one-off build
fvm dart run build_runner build --delete-conflicting-outputs

# Format generated l10n files if touched
dart format lib/l10n/

4. Coding Conventions

  • Riverpod 3.x: Prefer .value over valueOrNull. Avoid obsolete ProviderListenable type annotations. Prefer HTTP-layer mocking over global provider overrides.
  • Formatting: Page width 100, single quotes, strict casts and inference (analysis_options.yaml).
  • Translations: Hardcoded English initially during prototyping; migrate to lib/l10n/app_en.arb once stabilized.

5. Running & Runtime Validation

To run the application locally on Linux desktop:

Running Desktop AppBash
fvm flutter run -d linux

Runtime validation is mandatory for user-visible work: automated unit tests can pass while layout is visually clipped or sound synthesis fails. Exercise the feature interactively before opening a pull request.
